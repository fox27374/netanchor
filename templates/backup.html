Backup & Restore

Encrypted full-instance backup

Includes CA keys, certificates, profiles, users, HTTPS identity and SCEP history.

Choose a password of at least 12 bytes; if lost, the backup cannot be recovered.

What is included and how the password is used

A backup contains a complete snapshot of logical data: CA private keys, certificates, profiles, users, HTTPS identity, SCEP journal and history, and all trash records. Changes on both listeners pause briefly during the snapshot, then resume automatically.

Choose a unique password of at least 12 bytes (maximum 1024). A long random passphrase is recommended. The password is never stored. If lost, the backup cannot be recovered. Existing CA passphrases are still required after restore.

Replace this instance

Restore replaces all data and shuts down NetAnchor. If configured with a restart policy, containers restart automatically; standalone binaries must be started manually.

Warning: Your current account may disappear and be replaced. All unused SCEP challenges are invalidated. Sign in with an account from the backup after restart.
Restore process and limitations

The archive is validated and staged before activation. Once restore begins, it shuts down NetAnchor to prevent concurrent data access. Sign in using an account from the backup after the service restarts.

Restoring an older snapshot removes later records, users and policy edits, but does not revoke certificates already distributed—those remain valid. Keep the source stopped when moving an instance. Deployment configuration and external unlock secrets are not included in backups.
