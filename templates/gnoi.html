Push to device (gNOI)

Before you push

This can rebind the device's own gRPC server. Installing a certificate can make the switch bind its gNMI/gNOI server to it (for example gnxi secure-trustpoint on IOS-XE). Revoking that certificate later can take the server down. This page has no revoke action. Use a certificate id you are prepared to rebind.

The device generates the key and CSR. NetAnchor signs the CSR under the selected CA and profile, and sends back the certificate and CA chain. No private key exists in NetAnchor. Only the first installed certificate is supported: an existing certificate id is refused. IOS-XE only (Cisco Catalyst 9000, tested on 17.18.2).

Credentials are used for this push only. They are not stored or logged.

Device

Targets must match NETANCHOR_GNOI_ALLOW. Blank means no targets are allowed.

Connects only to read the device certificate. Compare it with the device before you confirm.

Certificate

SANs come from this form. Any SANs in the device's CSR are ignored. The key is RSA 2048, which the device generates.

The push stops after 60 seconds. To cancel while it runs, use the browser's Stop button. Nothing is cleaned up on failure, and no revoke is attempted.
